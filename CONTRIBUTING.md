# Contributing

## Development workflow

1. Create a branch from `main`.
2. Keep catalogue data and imagery synthetic or confirm that publication rights are documented.
3. Run `npm test`, `npm run typecheck`, `npm run lint`, and `npm run build`.
4. Open a focused pull request that explains the user-visible change and validation performed.

## Repository rules

- Do not commit secrets, personal data, customer material, private prompts, or proprietary retrieval sources.
- Do not commit generated output, dependencies, caches, logs, local databases, screenshots, or test reports.
- Keep the concierge's claims limited to the configured catalogue.
- Add server-side validation and access controls before connecting the prototype to a backend.
- Update the README when setup, behavior, or architecture changes.
